# Error and performance monitoring

Status: locally verified on October 8, 2026, including source-map upload and Sentry MCP readback (see the [verification record](../history/sentry-verification-2026-10-08.md)). Enabled in dev and prod on October 25, 2026.

Sentry project `semyon-g7/oghma` receives web, server, edge and worker events, distinguished by the `service` tag. It remains disabled when no DSN is configured. The [homelab runbook](../../infra/HOMELAB.md) owns deployment targets and runtime environment locations.

## Configuration

| Setting                     | Where                      | Purpose                                                                           |
| --------------------------- | -------------------------- | --------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_SENTRY_DSN`    | App build                  | Public project DSN, compiled into browser and edge bundles                        |
| `SENTRY_DSN`                | App and worker runtime     | Server and worker project DSN                                                     |
| `SENTRY_ENVIRONMENT`        | Build argument and runtime | Separate `prod`, `dev`, and `verification` events                                 |
| `SENTRY_RELEASE`            | Build argument and runtime | Git commit, shared by app, worker and uploaded maps                               |
| `SENTRY_TRACES_SAMPLE_RATE` | Build argument and runtime | Fraction of operations traced, default `0.1` in production and `1` in development |
| `SENTRY_AUTH_TOKEN`         | Build secret only          | Upload source maps to `semyon-g7/oghma`                                           |

The app Dockerfile maps the environment, release and sample-rate build arguments to their `NEXT_PUBLIC_SENTRY_*` equivalents. Runtime changes cannot alter an already-built browser bundle. In a local Next.js checkout, set both public and server variants explicitly.

For a local release build, the Sentry wizard can save the upload credential in the ignored `.env.sentry-build-plugin`. Load it without printing it: `node --env-file=.env.sentry-build-plugin "$(command -v npm)" run build`. This credential file is also excluded from Docker build contexts.

The live Jenkins pipelines ([HOMELAB.md](../../infra/HOMELAB.md)) read `NEXT_PUBLIC_SENTRY_DSN` (or `SENTRY_DSN`) and `SENTRY_AUTH_TOKEN` from the environment's Jenkins env file at build time. The app image gets the DSN, Git commit and deployment environment as build arguments; the worker image gets the commit and environment and reads its DSN from the same env file at runtime. The token reaches Docker as a BuildKit secret, never a build argument or image environment variable, and the build log only says whether each value is set. Uploads are disabled when the token is absent. Maps generated by Sentry are deleted after upload.

Since 2026-10-25 both env files set `SENTRY_DSN` and `SENTRY_AUTH_TOKEN`. The token is the `jenkins-oghma` organisation token (`org:ci` scope only), kept separate from the wizard token used for local builds. Dev build `#412` and prod build `#161` were the first to upload source maps for their releases. Because the containers load the whole env file, the upload token is also present in the app and worker runtime environment.

## Coverage and privacy

- Next.js instrumentation captures request failures and browser errors. The root, route and editor error boundaries report rendering failures.
- `npm run worker` preloads the Node SDK before importing worker code. The worker image uses this same command and flushes pending events on graceful shutdown.
- Caught Winston errors are captured before log redaction. Existing console/file redaction remains in place. Pass the original exception as `{ error }` to retain its stack; a message-only log has only the logging call stack.
- Study jobs, Canvas jobs and chat jobs have named processing spans. Their child HTTP/database spans show where time is spent. Idle study polling does not create a processing span.
- A failed chat marks its processing span as an error even when partial output is saved and the queue handler returns normally. Explicit cancellation remains outside error reporting. Worker and chat failure handlers pass the original exception to retain its stack.
- Errors are unsampled. Traces are sampled. A 10% setting cannot guarantee that every slow operation is captured. Routine health-check spans are excluded.
- Request/response bodies, headers, cookies, query parameters, queue arguments, database values, AI inputs/outputs and stack variables are disabled at collection time.
- The outgoing filters also remove raw error text, breadcrumbs, extra context, arbitrary span attributes, SQL text and span links. Stack file/function/line information is retained. Unknown URL segments become `[id]` to avoid exporting note identifiers or share tokens.
- Every error uses the dummy IP `0.0.0.0` to prevent ingestion from inferring a location. Sentry's affected-user count therefore represents one shared placeholder, not real users. Uploaded source maps supply source-code context; runtime variables and document contents remain excluded.
- Replay, profiling, Sentry logs and metrics are not enabled by this integration. Existing optional anonymous counters are separate.

## Verification and rollout

1. Run targeted monitoring tests, type checking and the production build.
2. Use an isolated local app with synthetic settings, a `verification` environment and full trace sampling. Exercise an actual browser error and server error through the normal startup hooks. Remove temporary test routes afterward.
3. Query Sentry through its authenticated MCP for the new errors and spans. Open each issue and inspect its frames. An accepted envelope alone does not prove ingestion or readable stack traces.
4. Configure source-map upload, repeat with a fresh production build, and confirm mapped source locations before calling stack traces ready for production.
5. Deploy through the normal `dev` to `main` flow only after approval. Verify both app and worker releases, then inspect real production events and quota usage.
