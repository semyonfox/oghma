# Anonymous usage counts

Current source contract, reviewed October 4, 2026. Collection is disabled by default. No endpoint is selected in source. This document does not authorize deployment or collector activation.

Browser reporting requires both `NEXT_PUBLIC_TELEMETRY_ENABLED=true` and an explicitly configured `NEXT_PUBLIC_TELEMETRY_ENDPOINT`. The endpoint must be HTTPS or a relative same-origin proxy path without a query or fragment. Global Privacy Control, Do Not Track and the disable control on Privacy and Settings suppress reports. The only saved telemetry preference is a disabled/enabled boolean for this browser. No visitor identifier, journey state or retry queue is created.

Payloads contain exactly `version`, `app`, `kind`, `name`, `surface` and `route`. Names and route categories are closed enums in `src/lib/telemetry.ts`. Counts describe screens and completed actions; errors describe fixed categories. URLs, referrers, account IDs, input text, notes, error messages and stacks are excluded. Requests omit credentials and referrers, reject redirects, time out after two seconds and never retry. Limits are twenty attempts per minute, two hundred per app lifetime, one in-flight request and one occurrence of each error category per route per minute. The server proxy uses a replenishing twenty-attempt-per-minute global bound and one in-flight request, without a browser lifetime cap or cross-user error deduplication. Reporting failure never changes the study or form workflow.

The retained `/api/marketing/events` path accepts only the new contract. It returns without reading a body when disabled or when a privacy signal is present, bounds enabled bodies to 1024 bytes, and forwards only to an explicitly configured HTTPS `TELEMETRY_ENDPOINT` with `TELEMETRY_ENABLED=true`. Server configuration remains authoritative for this proxy. Dedicated ingestion proxies must strip request metadata and disable access logging before any separately authorized deployment.

The self-hosted collector aggregates by UTC day, retains count totals for thirty days and error totals for fourteen days, and exposes no public statistics API. The previous local acquisition dashboard and account-activation collection are retired. Historical marketing rows are neither read by the dashboard nor removed by this change; any historical purge needs a separate reviewed data operation.

Operational Winston diagnostics are separate. Each transport receives only a fixed severity/category, service name and an optional HTTP status class. Raw text, stacks, nested metadata, request traces and account identifiers are discarded. The duplicate-account security anomaly retains its fixed category. Import diagnostics use this boundary; storage helpers emit fixed categories without caller content. Rotating operational files retain the existing fourteen-day bound. Authentication lockout, Redis rate limiting and the separate `rate_limit_log` security audit remain functional; their identifiers never become anonymous-report dimensions. These source checks do not establish deployed proxy logs or collector retention.
